# Token-saving ideas (backlog, from v1.4.0 review, rechecked on v1.5.0)

Status: implemented 1-5 (v1.6.0), 7 (v1.7.1), 9-10 (v1.7.1, partly), 12 (evals/), 6 (implemented v1.9.0, saving not measured (see evals/README.md token log)), 8 (team/autopilot only, v1.9.0), 11 (v1.9.0), 13 (delegation startup measured v1.11.0: no change, see below); open: none.

Since v1.5.0: `rules.md` is also injected on resume (idea 3 matters more), and every change must pass `node scripts/validate.mjs` (idea 4 must keep its cross-references valid).

## High impact, low effort
1. PostToolUse hook that auto-trims Bash output (e.g. last 40 lines + error lines), with a bypass. Trimming is enforced by the harness instead of relying on the model to add `tail`.
2. PreToolUse hook that blocks Opus Edit/Write outside `docs/prd/`. "Opus never edits" becomes guaranteed, so its prompt text can shrink.
3. Shrink `hooks/rules.md` (19 lines -> ~6); move detail into `on`. It is injected on every startup/clear/compact.
4. Split `skills/on/SKILL.md` into core + references (escalation, review, API errors) read on demand; team/autopilot currently load all of `on`.
5. `verify` script generated by `/orchestrator:init` (e.g. `.claude/verify.sh` with pipefail + tail + one summary line), so verification is one command with compact output.

## Medium impact
6. Cache-friendly brief order: fixed parts (TYPE, report format, lessons) first, variable parts last.
7. `effort` in agent frontmatter: haiku-coder `low`, sonnet-dev `medium`.
8. `budget=<N>k` argument for on/team/autopilot: sum tokens from completion notices; over budget -> stop and write a checkpoint.
9. Sonnet escalation sends `git diff -U1` + error instead of whole files; Opus verifies with `git diff -U1` by default.
10. Middle review tier: `opus-reviewer` only for schema/auth/security; other large work uses Haiku SCAN + `git diff --stat`.

## Longer term
11. `learned-errors` lesson: verified "error pattern -> cause -> fix" entries, so repeated errors skip TRIAGE.
12. Eval suite (`claude plugin eval`) with 3-5 standard scenarios logging tokens per version, to prove savings and catch rule regressions.

## Done in v1.7.1 (second audit)
- Smarter trim (only over 80 lines and 4000 chars; keeps first 3 lines; no line-trim of diff/show, cat, jq, Get-Content, type, JSON) and capped session index (20 lessons, 5 newest checkpoints).
- Guard reads only the last 512 KB of the transcript.
- Leaner flow: no COMMIT trailers, SCAN only for diffs over 5 files, small fixes batched into one delegation, agent reports max 8 lines, no background executors, lesson saves gated on a failure/escalation/correction.
- Agent `effort` levels (idea 7 done).

## Measured in v1.11.0: per-delegation startup

- R3 (2 runs): haiku-coder empty-task call 10,567 / 10,820 tokens (startup 10.56k, cached prefix 6,258); 1-3 tool task call 10,843 / 11,246; the task part of a 1-file CREATE (call2 - call1) is 276 and 426 tokens (about 0.3-0.4k). The 10.56k startup comes from call 2 (call 1 startup is not in the trace). opus-reviewer is 9.08k in R3; planner evidence is 9.2-9.3k for opus-planner/reviewer.
- Plugin-controlled share: the agent file body, about 0.9k for `haiku-coder` (under 10%).
- Decision: no reduction. Trimming `agents/haiku-coder.md` saves under 1k per delegation and risks TYPE-rule regressions. The real lever is fewer delegations: bundling, `SendMessage` reuse, the short path. All of these are already rules.
- Revisit only if R3 shows the plugin-controlled share above 3k.
