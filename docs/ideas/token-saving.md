Status: implemented 1-5 (v1.6.0), 7 (v1.7.1), 9-10 (v1.7.1, partly), 12 (evals/), 6 (implemented v1.9.0, saving not measured (see evals/README.md token log)), 8 (team/autopilot only, v1.9.0), 11 (v1.9.0), 13 (delegation startup measured v1.11.0: no change, see below); open: 13 (see "Proposed after v1.11.1"; the 13 above is the older startup-measurement item), 16 partly done (v1.12.0), 18 done (v1.12.0), 14, 15 and 17 done (v1.14.0).

Since v1.5.0: `rules.md` is also injected on resume (idea 3 matters more), and every change must pass `node scripts/validate.mjs` (idea 4 must keep its cross-references valid).

## High impact, low effort
1. PostToolUse hook that auto-trims Bash output (e.g. last 40 lines + error lines), with a bypass. Trimming is enforced by the harness instead of relying on the model to add `tail`.
2. PreToolUse hook that blocks Opus Edit/Write outside `docs/prd/`. "Opus never edits" becomes guaranteed, so its prompt text can shrink.
3. Shrink `hooks/rules.md` (19 lines -> ~6); move detail into `on`. It is injected on every startup/clear/compact.
4. Split `skills/on/SKILL.md` into core + references (escalation, review, API errors) read on demand; team/autopilot currently load all of `on`.
5. `verify` script generated by `/orchestrator:init` (e.g. `.claude/verify.sh` with pipefail + tail + one summary line), so verification is one command with compact output.

## Medium impact
6. Cache-friendly brief order: fixed parts (TYPE, report format, lessons) first, variable parts last.
7. `effort` in agent frontmatter: haiku-coder `low`, sonnet-dev `medium`.
8. `budget=<N>k` argument for on/team/autopilot: sum tokens from completion notices; over budget -> stop and write a checkpoint.
9. Sonnet escalation sends `git diff -U1` + error instead of whole files; Opus verifies with `git diff -U1` by default.
10. Middle review tier: `opus-reviewer` only for schema/auth/security; other large work uses Haiku SCAN + `git diff --stat`.

## Longer term
11. `learned-errors` lesson: verified "error pattern -> cause -> fix" entries, so repeated errors skip TRIAGE.
12. Eval suite (`claude plugin eval`) with 3-5 standard scenarios logging tokens per version, to prove savings and catch rule regressions.

## Measured in v1.11.0: per-delegation startup

- R3 (2 runs): haiku-coder empty-task call 10,567 / 10,820 tokens (startup 10.56k, cached prefix 6,258); 1-3 tool task call 10,843 / 11,246; the task part of a 1-file CREATE (call2 - call1) is 276 and 426 tokens (about 0.3-0.4k). The 10.56k startup comes from call 2 (call 1 startup is not in the trace). opus-reviewer is 9.08k in R3; planner evidence is 9.2-9.3k for opus-planner/reviewer.
- Plugin-controlled share: the agent file body, about 0.9k for `haiku-coder` (under 10%).
- Decision: no reduction. Trimming `agents/haiku-coder.md` saves under 1k per delegation and risks TYPE-rule regressions. The real lever is fewer delegations: `SendMessage` reuse, the short path. The multi-task bundling rule tried during 1.11.0 was removed (no measured effect); housekeeping bundling (v1.8.2, `orchestrator:on` token rules) stays. Cost is in Opus (main session turns and opus-planner/opus-reviewer), not in haiku-coder delegations; report cost by model (scripts/trace-tokens.mjs), not raw tokens.
- Revisit only if R3 shows the plugin-controlled share above 3k.

## Proposed after v1.11.1 (16 partly and 18 done in v1.12.0; 14, 15 and 17 done in v1.14.0; rest not implemented)

13. Direct-edit lane when the main model is already cheap (Haiku/Sonnet main) for 1-3 line edits: a Haiku -> Haiku delegation is pure overhead (~10k startup). Changes the core "main session never edits" rule: needs an owner decision.
    - First slice (cycle 018, proposal): scope is a non-Opus main session, 1 file, at most 3 changed lines, old and new text known, and the user explicitly says "edit directly". Mechanism options: (a) a one-shot hook allowance for that edit, or (b) the existing `/orchestrator:off` for one edit. Measure by comparing the `plain-edit-ablation` and `on-small-edit` eval cases; gate: at most 60k tokens per run against 172k with the plugin and 51k without (evals/README.md:93), and pass rate unchanged. Status: owner decision; guard unchanged.
14. **Done (v1.14.0).** Read guard hook: warn or deny a main-session Read of a large file without `offset`/`limit`; whole-file reads are the largest token sink no hook guards yet.
15. **Done (v1.14.0).** Trim-hook statistics: log lines/chars saved per call to the store and show totals in `/orchestrator:status`, so trim thresholds are tuned from data. Shipped as the TRIM row in `/orchestrator:status` (`hooks/trim-output.mjs --stats`).
16. **Partially done (compare script; scheduled run is opt-in).** Token regression gate in CI: run the eval suite on pull requests and fail when tokens rise more than X% over the stored baseline (builds on the plugin-eval-suite work).
17. **Done (v1.14.0).** Store key from repo identity (git remote origin URL; the folder path when there is no remote) instead of the folder path, so lessons survive a moved or re-cloned repo; keep the path key as fallback and migrate. Shipped for new stores; an existing path-based store keeps being used (no migration).
18. **Done.** Checkpoint expiry: mark checkpoints older than N days in the session-info line and offer deletion; stale ones are printed at every session start.
