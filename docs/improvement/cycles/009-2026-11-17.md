## New ideas

### IC-092 Proposal: cache-break detector in budget (flag turns where cache reads collapse and name the turn)

- Tier: safe bet
- Why extraordinary: users see which turn broke the prompt cache and what it cost, instead of only token totals; cache reads dominate the bill.
- Code anchor: scripts/budget.mjs:65-69
- Sources: https://codex.danielvaughan.com/2026/07/28/token-reduction-is-not-cost-reduction-prompt-cache-economics-codex-cli-tool-output-compaction-billing/ (2026-07-28); https://arxiv.org/pdf/2609.26779 (2026-09, body unread)
- First slice + verify: budget.mjs prints `cache-breaks: N` with the turn index where cache_read_input_tokens drops over 50% while context stays similar; verify `node scripts/validate.mjs` with a new smoke fixture.
- Full effort: S
- Confidence: 2
- Risks: heuristic threshold may misfire after compaction (expected break); source is a blog, not a primary study.

### IC-093 Proposal: guard-edit denial streak switches to stop-and-ask after 3 denials in a row

- Tier: safe bet
- Why extraordinary: today the main session can loop on denied edits and burn turns; after 3 consecutive denials the guard tells it to stop and ask the user, like auto mode's denial thresholds.
- Code anchor: hooks/guard-edit.mjs:22-23
- Sources: https://anthropic.com/engineering/claude-code-auto-mode (2026-03-25)
- First slice + verify: count consecutive denials per session in the OS temp dir; the 3rd denial reason adds "stop and ask the user"; reset on any allowed edit; verify `node scripts/validate.mjs` smoke with 3 denials.
- Full effort: S
- Confidence: 2
- Risks: counter file per session must be atomic and cleaned; wording must not confuse delegation.

### IC-094 Proposal: eval CI runs only the cases affected by changed skills, hooks or agents

- Tier: safe bet
- Why extraordinary: a full eval run costs real API credit (the last run failed on credit balance); running only cases whose skills, hooks or agents changed makes eval cheap enough to run on every PR.
- Code anchor: .github/workflows/eval.yml:64 (CASE defaults to all cases)
- Sources: https://www.fast.io/resources/ai-agent-prompt-regression-testing.md (undated); https://medium.com/@alexrodriguesj/testing-llm-prompts-like-code-regression-evals-in-ci-cd-with-promptfoo-5242b4dcb9be (undated)
- First slice + verify: an optional `touches:` list in each case.yaml plus scripts/eval-select.mjs that maps `git diff --name-only` to case names; verify validate smoke.
- Full effort: M
- Confidence: 3
- Risks: a wrong map silently skips a regression; keep a manual all-cases run.

### IC-095 Proposal: delegation outcome ledger that turns past PASS/FAIL per tier into routing hints

- Tier: ambitious
- Why extraordinary: escalation rules are fixed thresholds; a ledger of each delegation (tier, files, attempts, PASS/FAIL, tokens) lets the orchestrator say "tasks in hooks/ failed haiku 3 of 4 times, start with sonnet-dev", following research that early trajectory signals predict when to escalate.
- Code anchor: hooks/hooks.json:32,42 (Agent|Task only on PreToolUse)
- Sources: https://arxiv.org/abs/2607.00053 (2026-06-30); https://huggingface.co/papers/2607.11399.md (2026-07, summary only)
- First slice + verify: PostToolUse Agent|Task hook appends one JSON line per delegation to <store>/delegations.jsonl; status shows per-tier pass rate; verify validate smoke.
- Full effort: M (slice) / L (hints)
- Confidence: 2
- Risks: parsing STATUS from agent output is brittle; ledger growth needs a cap; cheap-first savings can be false economy.

### IC-096 Proposal: export orchestration runs as OpenTelemetry GenAI spans (invoke_agent, execute_tool, token usage)

- Tier: ambitious
- Why extraordinary: runs become viewable in any OpenTelemetry backend (Jaeger, Langfuse, Grafana) as a span tree of agents and tools with token usage, not only as text tables.
- Code anchor: scripts/trace-tokens.mjs:79,128
- Sources: https://github.com/open-telemetry/semantic-conventions-genai (undated); https://www.truefoundry.com/blog/opentelemetry-genai-semantic-conventions (2026, secondary)
- First slice + verify: scripts/otel-export.mjs <transcript> writes an OTLP JSON file with invoke_agent and execute_tool spans and gen_ai usage attributes, content capture off; verify validate smoke parses the output.
- Full effort: M
- Confidence: 2
- Risks: the spec is at Development stability, so pin the schema version; attribute names unverified against the new repo.

### IC-097 Proposal: PRD task table compiled into a file-dependency DAG that derives parallel lanes and skips unchanged tasks

- Tier: moonshot
- Why extraordinary: team and autopilot lanes are split by hand; compiling the PRD task table into a file-dependency DAG derives file-disjoint lanes automatically and skips tasks whose inputs did not change on a rerun, like a build system.
- Code anchor: skills/team/SKILL.md:3
- Sources: https://arxiv.org/pdf/2603.16104v1 (2026-03); https://arxiv.org/pdf/2511.19635 (2025-11)
- First slice + verify: scripts/plan-dag.mjs reads a PRD task table (task, files) and prints file-disjoint parallel lanes; verify validate smoke with a sample PRD.
- Full effort: L
- Confidence: 1
- Risks: research prototypes only; PRD format must become stricter; hidden dependencies between files are not visible from paths.
